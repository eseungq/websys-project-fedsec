## ① 모델 역추적 공격
> 서버가 개별 클라이언트의 그래디언트를 볼 수 있다고 가정. 공개 DLG 코드로 입력 이미지를 복원하며, 이미지 한 장의 1회 그래디언트를 사용하는 별도 소규모 실험으로 진행

**구현 내용**
- 공개 DLG 코드의 구성을 따름: 시그모이드 LeNet(가중치 U(−0.5, 0.5)), 더미 이미지·soft label을 L-BFGS로 300회 최적화
- 피해자: 클라이언트 0의 이미지 한 장으로 1회 그래디언트 계산. 공격자는 이 그래디언트와 모델만 받습니다. **원본 이미지와 정답 레이블은 공격 함수의 인자가 아니고**, 평가(MSE)에만 씁니다
- 연합학습 본 실험과 분리된 `scripts/run_dlg.py`, CPU 고정
- 코드: `src/fedsec/attacks/dlg.py`, `src/fedsec/models/lenet.py`

**결과:** 노이즈가 없으면 이미지 5장 모두 MSE 0.000004\~0.00005로 원본과 구분되지 않습니다. 레이블도 5장 모두 맞힙니다.

## ② 내부자 협력 공격
> 전체 10개 중 악성 2개 지정. 같은 라운드에 참여한 악성 클라이언트들의 정상 업데이트를 평균하고 -5를 곱한 동일 벡터를 각각 제출

**구현 내용**
- 악성 2명은 시드로 고정 (시드 0: 2·3번, 1: 1·4번, 2: 5·7번)
- 라운드마다 참여자 전원이 정상 학습을 끝낸 뒤, 참여한 악성들의 정상 업데이트를 **단순 평균**(표본 수 가중 아님)하고 −5를 곱해 각자 같은 벡터를 제출
- 계산은 클라이언트 실행 프로그램 안에서만 합니다. 서버는 누가 악성인지 모릅니다
- 코드: `src/fedsec/attacks/collusion.py`의 `collusion_vectors`. 배수는 `configs/attack_defense.yaml`의 `attack.scale`(−5.0)

**결과 (2라운드 동작 확인):** 1라운드 악성 2명의 조작 전 노름 1.83·1.80 → 조작 후 둘 다 8.63. `clients.csv`에 조작 전(`update_norm`)·조작 후(`norm_submitted`) 노름이 남습니다.

## ③ 악성 참여자 수에 따른 처리
> 악성 참여자가 1명이면 자기 업데이트의 -5배를 제출하고, 0명이면 해당 라운드에는 공격을 적용하지 않음

**구현 내용:** ②의 평균을 "그 라운드에 참여한 악성" 기준으로 계산합니다. 1명이면 자기 업데이트만 평균되므로 자기 업데이트 × −5, 0명이면 바꿀 대상이 없어 공격이 없습니다.

**결과**
- 0명(공격 없음)·1명(−5배)·2명(같은 벡터)과 "평균은 표본 수 가중이 아닌 단순 평균"을 수치 예제 테스트로 확인 (`tests/test_collusion.py`)
- 부분 참여 동작 확인에서 악성 0명인 라운드는 `attack_applied=False`로 기록됨
- 시드 0 부분 참여 40라운드 동안 참여 악성 수: 0명 6회, 1명 21회, 2명 13회 → 세 경우가 본 실험에서 모두 실제로 나옵니다

## ④ 모델 역추적 방어
> 전송 전 그래디언트에 가우시안 노이즈 추가. 노이즈 없음·작음·큼의 수치는 팀이 정하고 기록하며, 같은 이미지와 복원 조건에서 MSE 비교

**구현 내용**
- 그래디언트 원소마다 평균 0, 표준편차 σ의 노이즈를 더한 뒤 공격자에게 넘깁니다
- σ 7단계(0, 1e-4, 1e-3, 3e-3, 1e-2, 3e-2, 1e-1)를 탐색하고 3개를 골랐습니다
- 같은 이미지 5장, 같은 모델·복원 초기값. 모델·더미 초기값·노이즈 시드를 따로 고정해 σ만 바뀌게 했습니다
- 값은 `configs/dlg.yaml`, 근거는 [3_DLG-결과.md](3_DLG-결과.md)

**결과**

| 수준 | σ | MSE (5장, 300회) | 복원 이미지 |
|---|---|---|---|
| 없음 | 0 | 0.000004\~0.00005 | 원본과 같음 |
| 작음 | 1e-2 | 0.05\~0.08 | 노이즈가 심하지만 형체가 남음 |
| 큼 | 1e-1 | 0.26\~0.31 | 형체 없음 (무작위 시작점과 같은 수준) |

- 레이블은 σ 1e-1에서도 5장 모두 복원됩니다 → 노이즈는 이미지만 지킵니다
- dog 이미지(σ 1e-2)는 복원이 멈췄는데, 노이즈가 아니라 최적화 초반 폭주였습니다 (복원 초기값만 바꾸면 정상) → 6단계 원인 분석 사례 후보

## ⑤ 내부자 협력 방어
> 업데이트 노름 클리핑 후 FedAvg와 좌표별 중앙값 집계를 각각 구현. 클리핑 상한은 정상 실험을 참고해 팀이 정하고 비교 실험 전체에서 고정

**구현 내용**
- **클리핑 후 FedAvg** (`clip_fedavg`): 각 업데이트 u에 `min(1, 3.5 / ‖u‖)`를 곱해 노름을 3.5 이하로 줄인 뒤 표본 수 가중 평균. 노름은 모든 파라미터를 이은 L2
- **좌표별 중앙값** (`median`): ⑥ 참고. 표본 수 가중 없음
- 서버 집계 방식을 `--aggregator fedavg | clip_fedavg | median`으로 고릅니다. 중앙값 전 클리핑은 두 방어를 따로 비교하려고 기본으로 끔(`--clip-before-median`으로 켬)
- 상한 3.5는 정상 FedAvg의 업데이트 노름 분포를 보고 정했고, 모든 환경·시드에서 같은 값을 씁니다
- 코드: `src/fedsec/defenses/clipping.py`, `src/fedsec/defenses/median.py`

**결과: 상한 3.5의 근거 (정상 FedAvg, 40라운드, 업데이트 400개)**

| 분할 | 중앙값 | 90% 지점 | 최대 | 3.5에 잘리는 비율 |
|---|---|---|---|---|
| IID | 2.65 | 3.40 | 3.67 | 5.2% (후반 라운드) |
| 레이블 편향 | 2.23 | 2.74 | 3.19 | 0% |

- 정상 업데이트는 거의 잘리지 않습니다. 공격 벡터(약 8.6)는 방어 후 노름이 3.5로 줄었습니다 (`clients.csv`의 `norm_defended`)
- 노름은 라운드가 갈수록 커집니다(IID 1라운드 1.8 → 40라운드 3.6). 그래서 초반 값이 아니라 전체 라운드 분포로 정했습니다
- 자세한 근거: [1_학습설정-결과.md](1_학습설정-결과.md) 실험 7

## ⑥ 중앙값 계산과 악성 ID
> 짝수 개의 중앙값은 가운데 두 값의 평균 사용. 방어 함수에 악성 ID 정답을 전달하지 않음

**구현 내용**
- `torch.median`은 짝수 개에서 아래쪽 값을 돌려주므로 쓰지 않고, 좌표마다 정렬해 가운데 두 값을 평균합니다
- 방어 함수의 인자는 업데이트 목록과 표본 수뿐입니다. 서버도 악성 ID를 모릅니다. 악성 ID는 클라이언트 쪽 `config.yaml`의 `plan`에만 분석용으로 남습니다

**결과:** 손으로 계산한 수치 예제 테스트 (`tests/test_defenses.py`)
- 홀수 개 → 가운데 값, 짝수 개 → 가운데 두 값 평균, 좌표마다 따로
- 이상치 하나가 결과를 크게 바꾸지 못함
- 클리핑: (3, 4)는 노름 5 → 상한 1이면 (0.6, 0.8)

## 내부자 공격·방어 비교 결과
기준 환경(참여 100%, 지연 없음, IID), 40라운드, 최종 테스트 정확도. 환경 4개 전체 표와 시드별 값: [4_운영환경.md](4_운영환경.md) ⑤

| | FedAvg | 클리핑 (3.5) | 중앙값 |
|---|---|---|---|
| 정상 (평균) | 76.22% | 76.26% | 76.13% |
| 공격 (평균) | 발산 (13 / 11 / 17라운드) | 67.46% | 69.15% |
| 정상 손실 (시드 0 / 1 / 2) | | +0.18 / −0.15 / −0.14%p | +0.25 / +0.15 / −0.13%p |

- **공격 피해:** 공격 + FedAvg는 세 시드 모두 발산해 40라운드 값이 없습니다. 발산 직전 모델도 테스트 정확도 10.00%라, 그 값으로 빼면 66.22%p다(학습 길이가 달라 참고값)
- **방어 개선:** 두 방어 모두 발산을 막았습니다. 공격 + FedAvg가 발산해 명세 정의대로는 계산하지 않았고, 발산 직전 모델 기준 참고값은 클리핑 57.46, 중앙값 59.15%p다. 정상 FedAvg보다는 클리핑 8.77, 중앙값 7.07%p 낮습니다
- **중앙값이 클리핑보다 세 시드 모두 높습니다** (+1.70 / +1.97 / +1.42%p). 클리핑은 줄인 공격 벡터(노름 3.5)도 평균에 넣고, 중앙값은 좌표마다 가운데 값을 골라 극단값의 영향을 제한한다는 차이가 있습니다. 다만 악성 값이 가운데 자리에 들어가면 중앙값도 악성 값이 될 수 있습니다(정상 8개 −4·−3·−2·−1·1·2·3·4, 악성 2개 0.5 → 0.5). 이 차이가 관측된 정확도 차이의 원인인지는 6단계에서 확인합니다
- **정상 손실은 시드 간 차이 수준**(−0.15\~+0.25%p)으로, 기준 환경에서 방어를 켜도 정상 성능은 거의 그대로입니다
