## ① 학습 로그
> 학습 로그: 실험·라운드·클라이언트 ID, 공격·방어, 표본 수, 정확도, 조작·방어 전후 업데이트 노름, 채택·제외 사유와 시간 기록

**구현 내용:** 서버를 거친 실행(`run_server_experiment.py`, `run_main.py`)의 결과 폴더 `experiments/<name>/`에 남는다.

| 파일 | 한 줄 단위 | 주요 열 |
|---|---|---|
| `clients.csv` | 라운드 × 클라이언트 (참여하지 않은 클라이언트도 한 줄) | `experiment`, `round`, `client`, `malicious`, `selected`, `attacked`, `defense`, `num_samples`, `train_loss`, 조작 전 `update_norm`, 제출(조작 후) `norm_submitted`, 방어 후 `norm_defended`, `accepted`, `reason`(제외 사유), `virtual_finish`(가상 완료 시각), `train_sec`, `comm_sec` |
| `rounds.csv` | 라운드 | `val_acc`, `val_loss`, 선택·채택·`late` 수, 악성 비율 2가지, `attack_applied`, `updated`, `skip_reason`, `aggregator`, `virtual_elapsed`(가상 경과 시간), 실제 시간(`train_sec`, `comm_sec`, `total_sec`) |
| `class_acc.csv` | 라운드 × 클래스 | 클래스별 맞힌 수·전체 수·정확도 (`split`: val, test) |
| `client_acc.csv` | 라운드 × 클라이언트 | 분포 가중 정확도 = Σ (클라이언트의 클래스 비율 × 클래스 정확도) |
| `server/` | 서버 쪽 기록 | `server_rounds.csv`(집계 기록), `exclusions.csv`(제외된 제출과 사유), `server.log`(원시 로그, 커밋 안 함) |
| `summary.json` | 실행 1회 | 최종 검증·테스트 정확도, 갱신 안 한 라운드 수, 가상·실제 시간 합계, 발산한 라운드(`diverged_round`, 없으면 null)와 끝낸 라운드 수(`rounds_completed`). 모델 저장 뒤 마지막에 쓴다 |

- 가상 시간(채택 판정용)과 실제 실행 시간은 따로 기록한다
- 클라이언트별 성능: 클라이언트마다 따로 떼어 둔 평가 데이터가 없어서, 공통 평가 데이터의 클래스별 정확도를 각 클라이언트의 학습 데이터 클래스 비율로 가중한다

**확인:** 공격을 켠 12조합 2라운드 실행에서 선택된 클라이언트 행에 빈칸이 없었다. 공모 벡터의 조작 전 1.83 → 조작 후 8.63 → 클리핑 후 3.5가 한 줄에 남는다.

## ② 복원 로그
> 복원 로그: 이미지 식별 정보, 노이즈 설정, 복원 반복 횟수, MSE와 복원 이미지 기록. 원본과 정답은 공격의 입력으로 제공하지 않고 평가에 활용

**구현 내용:** `experiments/3_dlg/<name>/`
- `results.csv`: 이미지 × σ × 반복 횟수마다 한 줄. `image_index`, `label`, `class`, `sigma`, `iterations`, `mse`, `pred_label`, `label_correct`, 그래디언트 차이, 노이즈 크기, 걸린 시간
- `trajectory.csv`: 10회마다 그래디언트 차이와 MSE (복원이 덜 됐는지 판단용)
- `summary.png`: 원본 | σ별 복원 이미지를 한 장에. 개별 복원 이미지는 `dlg_images/` (용량 때문에 커밋 안 함, 다시 실행하면 생김)
- 공격 함수(`reconstruct`)의 인자는 모델·그래디언트·이미지 크기·반복 횟수·초기값 시드뿐이다. 원본 이미지와 정답 레이블은 MSE와 레이블 정답 여부를 계산하는 평가에만 쓴다

## ③ 재실행할 수 있게 저장
> 실험 설정·시드·데이터 분할과 필요한 모델 상태를 저장하여, 분석 대상으로 선택한 라운드나 복원 실험을 다시 실행할 수 있도록 구현

**구현 내용**
- `config.yaml`: 실제로 쓴 전체 설정(학습 값, 시드, 분할 파일 경로, 환경, 공격·방어, 악성·지연 ID와 참여 규칙)
- `env.json`: 기기, 라이브러리 버전, 커밋 ID
- 분할 파일: IID는 레포 루트 `configs/splits/iid_seed0.json`, 레이블 편향은 이 폴더의 `configs/splits/label_skew_a0.5_seed0.json` (모두 커밋)
- 모델 상태: `models/round_XXX.pt` = 라운드 0, 5의 배수, 마지막 라운드 집계 후 전역 모델 (간격 `--save-every`, 40라운드면 10개). 실행마다 약 14MB라 커밋하지 않는다
- 발산한 공격 실험은 발산 전 라운드의 모델도 저장하고, `final_model.pt`도 그 모델이다 (로컬 학습 손실·업데이트, 제출할 업데이트의 노름(공격 벡터 포함, float32 범위 초과), 집계 뒤 전역 모델·검증 손실에 NaN·inf가 생기면 그 라운드는 기록하지 않고 끝낸다)
- 부분 참여 일정은 (시드, 라운드)로 다시 계산되므로 따로 저장하지 않아도 같다
- DLG는 `config.yaml`의 값(이미지, σ, 반복 횟수, 시드 3개)으로 같은 복원을 다시 만든다. 다시 돌려 MSE가 소수점 끝까지 같음을 확인했다

**아직:** 저장한 모델에서 특정 라운드부터 조건을 바꿔(특정 클라이언트의 조작 해제, 방어 방식 변경) 다시 돌리는 도구. 6단계 원인 분석에서 만든다.

## ④ 공격 피해·방어 개선·정상 손실
> 공격 피해 = 정상 FedAvg - 공격 FedAvg, 방어 개선 = 공격+방어 - 공격 FedAvg, 정상 손실 = 정상 FedAvg - 정상+방어

**구현 내용:** 계산에 필요한 실행 6가지(정상·공격 × FedAvg·클리핑·중앙값)를 환경·시드마다 `run_main.py`가 만들고, 각 `summary.json`에 최종 테스트 정확도(`final_test_acc`)가 남는다. 요약은 `experiments/4_main/runs.csv`.

**계산:** `scripts/compare_main.py`(계산은 `src/fedsec/experiment/comparison.py`)가 `runs.csv`에서 같은 환경·시드끼리 뺀다. 방어는 클리핑과 중앙값 각각 계산한다. 예정 조합(기본은 `run_main.py`와 같은 환경 4 × 시드 0·1·2)과 `runs.csv`가 정확히 같아야 하고, 실행마다 완료 라운드가 목표(`base.yaml`의 40, `--rounds`로 바꿈)와 같거나 발산 기록(공격 실험만, 발산 라운드 1\~목표, 완료 라운드 = 발산 − 1)이 맞아야 한다. 빠지거나 예정에 없는 실행, 끝나지 않은 실행, 중복 실행, 0\~1 밖의 정확도, 열 수가 머리줄과 다른 행(잘린 파일), 1라운드 발산이 아니거나 검증·테스트 정확도가 남은 `diverged` 행, `done`인데 1라운드에 발산한 행(평가할 모델이 없으므로 `diverged`여야 함)이 있으면 파일을 쓰지 않고 멈춘다(같은 prefix에서 `--envs baseline`만 돌려 `runs.csv`가 18회로 바뀌어도 72회 표를 덮어쓰지 않음).

```bash
python scripts/compare_main.py                    # experiments/4_main/runs.csv → experiments/4_main/_tables/
```

**결과:** 본 실험 72회로 만든 값이 [4_운영환경.md](4_운영환경.md) ⑤에 손으로 계산해 적은 표와 모두 같다.

## ⑤ 표시 방법
> 위 차이는 같은 환경·시드의 최종 테스트 정확도로 계산하고 %p로 표시. 시드별 값과 평균을 함께 보고하며, 음수 결과도 그대로 기록

**구현 내용:** 일괄 실행은 최종 테스트 정확도가 없거나 0\~1 사이 숫자가 아닌 결과를 완료로 치지 않는다. 예외는 1라운드 집계 직후 발산한 공격 실험(`runs.csv` 상태 `diverged`)으로, 평가할 모델이 없어 정확도가 비어 있다. 비교표는 발산한 실행이 들어간 칸을 숫자 대신 "발산 (13 / 11 / 17라운드)"처럼 시드별 발산 라운드로 표시한다(1라운드 발산도 "발산 (1라운드)"). 일부 시드만 발산하면 그 시드만 발산으로 적고 평균은 내지 않는다. 발산 전 모델로 평가한 정확도를 그대로 뺀 값은 학습 길이가 달라 주 표에 섞지 않고 참고 표로 따로 둔다 ([4_운영환경.md](4_운영환경.md) 한계).

결과 파일 (`experiments/<prefix>/_tables/`)
- `comparison.md`: 최종 테스트 정확도 표, 명세의 세 값 표, 발산한 칸이 있으면 참고 표
- `comparison.csv`: 환경 × 지표 × 시드마다 한 줄. `value_pp`(주 표, 발산하면 빈칸), `reference_pp`(참고), `diverged_rounds`
- `accuracy.svg`: 환경별 6조건의 정확도 평균 막대그래프. 한 시드라도 발산한 조건은 막대 없이 '발산'으로 표시

**결과:** 음수(예: 지연 환경 정상 손실 클리핑 −0.45%p)도 그대로 표시된다. 그래프는 표준 라이브러리로 SVG를 직접 그린다(matplotlib 없이).

## ⑥ 악성 비율과 채택 규칙
> 전체 악성 비율과 실제 채택 악성 비율을 구분. 채택 수가 0이면 비율은 N/A, 3개 미만이면 모델을 갱신하지 않고 사유 기록

**구현 내용**
- `rounds.csv`에 두 비율을 따로 기록한다
  - `overall_malicious_ratio`: 지정된 악성 수 / 전체 10명
  - `accepted_malicious_ratio`: 채택된 업데이트 중 악성 비율. 채택 0개면 `N/A`
- 서버는 채택이 3개 미만이면 모델을 갱신하지 않고 `skip_reason`(`no_accepted`, `too_few_accepted`)을 남긴다. 모델 버전도 그대로다
- 클라이언트가 계산한 채택 판정이 서버 기록과 다르면 실행을 멈춘다 (로그를 믿을 수 있게)

**결과**
- 전체 악성 비율은 모든 환경에서 0.2 (2/10)
- 지연 환경: 실제 채택 악성 비율 0.29 (지연 3명이 빠지고 악성 2명은 채택, 2/7)
- 부분 참여: 실제 채택 악성 비율이 악성 2명이 함께 뽑힌 라운드는 0.4 (2/5), 0명인 라운드는 0.0
- 채택 0개(`N/A`)와 3개 미만(갱신 안 함)은 실제 환경에서는 생기지 않아 통합 테스트로 확인했다 (`tests/test_client_round.py`)
