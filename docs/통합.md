### 옮기면서 바꾼 것
- **기준 경로:** 스크립트·테스트가 개인 폴더를 기준으로 잡던 경로(`MEMBER_ROOT`)를 레포 루트(`ROOT`)로 바꿨습니다. 명령은 모두 레포 루트에서 실행합니다.
- **저장된 실험 설정:** 레이블 편향 실행 19개의 `config.yaml`에 남은 분할 파일 경로를 `members/이승규/configs/splits/…`에서 `configs/splits/…`로 고쳤습니다. 파일은 같고 위치만 바뀐 것이라, 일괄 실행기의 완료 판정(`run_main.py --dry-run`)이 72회 모두 "끝남"으로 유지됩니다.
- **`.gitignore`:** 개인 폴더의 규칙(서버 원시 로그 `server.log`, 상태 덤프 `server_status.json`)을 루트로 합쳤습니다.
- **의존성:** `torch>=2.10.0`으로 올렸습니다. 재실행 도구가 저장된 모델 파일(`.pt`)을 읽으므로, 배병욱 PR #9에서 체크포인트 역직렬화 취약점 대응으로 정한 최소 버전을 따랐습니다. 모델 파일은 항상 `weights_only=True`로 읽습니다.

## 3. 새로 만든 것

### 3-1. 재실행 도구 `scripts/replay.py`
명세 5단계 "분석 대상으로 선택한 라운드를 다시 실행할 수 있도록 구현"과 6단계 "같은 시작 모델과 참여 조건에서 특정 클라이언트의 조작을 해제하거나 방어 방식만 바꿔 재실행"에 해당합니다.

```bash
# 기준·공격·FedAvg·시드 0 실행의 5라운드 모델에서 출발, 악성 2번의 조작만 해제
python scripts/replay.py --run 4_main/baseline-attack-fedavg-s0 --from-round 5 --unmask 2
# 같은 출발점에서 방어만 중앙값으로 교체
python scripts/replay.py --run 4_main/baseline-attack-fedavg-s0 --from-round 5 --aggregator median
# 아무것도 바꾸지 않고 다시 돌려 원래 결과와 같은지 확인
python scripts/replay.py --run 4_main/baseline-normal-fedavg-s0 --from-round 35 --same
```

- 원래 실행의 `config.yaml`에서 학습 설정·환경·시드·악성/지연 ID를 그대로 가져오고, `models/round_XXX.pt`(라운드 K 집계 후 전역 모델)로 서버를 라운드 K+1부터 띄웁니다.
- 참여자·로컬 셔플·가상 시간은 모두 (시드, 라운드)로 정해지므로, 바꾼 조건 하나 말고는 원래 실행과 같습니다.
- 설정 파일이 원래 실행 뒤에 바뀌었으면 같은 조건이 아니므로 멈춥니다.
- 결과는 `experiments/6_replay/<원래 이름>-from<K>-<바꾼 조건>/`에 일반 실행과 같은 파일과 `replay.json`(원래 실행, 출발 라운드, 바꾼 조건, 원래 결과 요약)으로 남습니다.
- 모델 파일은 72회 실행마다 라운드 0·5의 배수·마지막(발산했으면 발산 직전) 라운드가 저장되어 있습니다. 용량 때문에 커밋하지 않으므로 실험을 돌린 PC에만 있습니다.

엔진에 더한 것 (기존 동작은 그대로):
- `ServerState(start_round=…)`: 저장된 라운드 다음부터 시작 (모델 버전은 0부터 셈)
- `load_global_state()`: 저장 모델을 `weights_only=True`로 읽고 키·shape·dtype·NaN을 검사
- `scripts/serve.py --start-round --init-model`: 위 두 가지를 서버 실행에 연결 (`experiments/` 아래 모델 파일만)
- `ClientPlan.unmasked`: 조작을 해제한 악성 ID. 해제한 악성은 남은 악성의 공모 평균에 끼지 않고 자기 정상 업데이트를 냅니다. 로그의 `malicious` 표시는 그대로라 "악성이지만 공격 안 함"이 구분됩니다.

### 3-2. 대시보드 `web/`
명세의 "중앙 Flask 서버 1개"를 지키기 위해, 연합학습 REST API와 대시보드를 **한 Flask 앱·한 포트**에서 함께 띄웁니다.

```bash
python web/app.py                      # http://127.0.0.1:8765/
```

| 모드 | 내용 |
|---|---|
| 조회형 | `experiments/` 아래 결과 폴더(본 실험 72회, 재실행 결과 포함)를 골라 라운드별 검증 정확도·손실, 참여 현황(선택·채택·지연 제외, 실제 채택 악성 비율), 클라이언트별 기록, 클래스별 정확도를 봅니다. 72회 비교표(공격 피해·방어 개선·정상 손실, 시드별·평균)와 DLG 결과(노이즈별 원본·복원 이미지, MSE)도 봅니다. 파일을 읽기만 합니다. |
| 실행형 | 환경·공격·집계·시드·라운드 수(최대 10)를 골라 짧은 실험을 실제로 돌리고 진행을 봅니다 (발표 시연용). 같은 서버의 상태를 새 실험 설정으로 바꾼 뒤 가상 클라이언트 실행 프로그램(`run_clients.py`)을 하위 프로세스로 띄웁니다. 한 번에 하나만 돌고, 결과는 `experiments/live/`(커밋 안 함)에 남습니다. |

| API | 역할 |
|---|---|
| `GET /status`, `GET /model`, `POST /update`, `POST /aggregate` | 연합학습 REST API (기존과 같음) |
| `GET /` | 대시보드 화면 |
| `GET /api/runs`, `GET /api/runs/<실행>` | 결과 폴더 목록, 한 실행의 기록 |
| `GET /api/comparison`, `GET /api/comparison/accuracy.svg` | 72회 비교표와 정확도 그래프 |
| `GET /api/dlg`, `GET /api/dlg/<실험>/images/<파일>` | DLG 결과와 이미지 |
| `POST /api/start`, `GET /api/status`, `POST /api/stop` | 실행형 시작·진행 상황·중지 |

- 안태현 PR #8의 화면 구성(탭, 카드, 그래프)을 바탕으로 했고, 서버 쪽 코드는 가져오지 않았습니다. 그래서 PR #8 리뷰에서 확인한 서버 쪽 문제(조작 해제가 동작하지 않음, 학습 길이가 다른 결과를 비교함, 중복 제출이 기존 제출을 지움)는 들어오지 않았습니다.
- 라운드 재실행 버튼은 빼고, `scripts/replay.py`로 만든 재실행 결과를 보여 주는 탭으로 바꿨습니다.
- 보안: 화면은 `createElement`·`textContent`로만 그립니다 (PR #8에서 지적된 `innerHTML` XSS 제거). 외부 CDN 없이 로컬 파일만 쓰고 CSP 헤더를 붙였습니다. 경로는 `experiments/` 안인지 확인하고, `/api/start` 입력은 허용 목록·범위로 검사합니다. 서버의 기존 규칙(127.0.0.1, Host 헤더 확인, POST는 JSON만)이 대시보드에도 그대로 적용됩니다.
- DLG 복원 이미지(`dlg_images/`)는 커밋하지 않으므로, 새로 받은 레포에서는 요약 그림(`summary.png`)과 MSE 표만 보입니다.
