## ① 기준
> 기준: 참여율 100%, 지연 없음, 클래스 분포가 비슷한 데이터

**구현 내용:** 매 라운드 10명 전원 참여, 지연 클라이언트 0명. 분할은 팀 공용 `configs/splits/iid_seed0.json`(레포 루트): CIFAR-10 학습 50,000장 → 클라이언트 10명 × 4,500장 + 검증 5,000장. 공식 테스트 10,000장은 최종 평가에만 쓴다.

**결과**
- 2라운드 확인: 매 라운드 10명 채택, 실제 채택 악성 비율 0.2, 가상 경과 시간 1.0
- 정상 FedAvg 40라운드 검증 정확도 76.38% (36\~40라운드 평균, 시드 0\~2 평균, [1_학습설정-결과.md](1_학습설정-결과.md))

## ② 지연
> 기준에서 고정된 3개 클라이언트만 가상 마감 시각 초과. 지연·마감 값은 팀이 정하고, 실제 순차 실행 시간과 분리하여 채택 여부 판정

**구현 내용**
- 가상 완료 시각 = 기본 계산 1.0 × (표본 수 / 4,500) + 지연 2.0(지연 클라이언트만). 마감 1.5
- 그래서 정상은 1.0으로 채택되고, 지연 3명은 3.0으로 **항상** 마감을 넘어 `late`로 제외된다 (클라이언트 표본 수가 모두 4,500장이라 라운드마다 같다). 설정 값을 바꿔 "지연 클라이언트만 마감 초과"가 깨지면 클라이언트가 학습 전에 멈춘다
- 지연 3명은 시드로 고정하고 악성과 겹치지 않게 뽑는다 (시드 0: 0·4·9번)
- 채택 여부는 가상 시각으로만 정한다. 실제 실행 시간(`train_sec`, `comm_sec`, `total_sec`)은 따로 기록한다

**결과 (2라운드 확인):** 매 라운드 선택 10, 채택 7, `late` 3. 악성 2명이 모두 채택되어 **실제 채택 악성 비율 0.29**(2/7)로 전체 악성 비율 0.2보다 높다. 가상 경과 시간 1.5(늦은 제출이 있으면 마감 시각).

## ③ 부분 참여
> 기준에서 라운드마다 10개 중 5개를 무작위 선택

**구현 내용:** (시드, 라운드)로 참여자 5명을 정한다. 공격 여부·집계 방식이 달라도 같은 라운드에는 같은 5명이 참여한다. 서버가 참여자를 알고, 참여자가 아닌 제출은 `not_selected`로 제외한다.

**결과**
- 매 라운드 정확히 5명 (테스트)
- 2라운드 확인: 1라운드 참여 2·3·5·6·7번(악성 2명, 공격 적용, 실제 채택 악성 비율 0.4), 2라운드 0·4·7·8·9번(악성 0명, 공격 미적용)
- 시드 0, 40라운드 동안 참여 악성 수: 0명 6회, 1명 21회, 2명 13회

## ④ 레이블 편향
> 기준에서 같은 데이터의 클라이언트 배정만 변경. 클라이언트별 표본 수는 유지

**구현 내용**
- IID 분할과 **같은 검증 세트, 같은 이미지 풀**에서 배정만 바꾼다
- 클라이언트별 클래스 비율을 Dirichlet(α = 0.5)로 뽑고, 클라이언트당 4,500장과 클래스별 장수를 정확히 맞춰 배정
- 분할 파일: `configs/splits/label_skew_a0.5_seed0.json` (이 폴더). 시드와 관계없이 이 분할을 쓴다
- 만드는 명령: `python scripts/make_split.py --kind label_skew --alpha 0.5 --seed 0`, 분포 보기: `--show-dist`

**결과**
- 행(클라이언트 4,500장)·열(클래스별 장수) 합과 검증 세트가 IID와 같음 (테스트)
- 치우침: 클라이언트마다 가장 많은 클래스가 22\~62%를 차지하고(IID는 약 10%), 100장 미만인 클래스가 1\~5개 있다. 가장 치우친 클라이언트 4는 클래스 2가 2,790장(62%)
- 정상 FedAvg 40라운드(시드 0, 서버 경유): 검증 정확도 **73.80%** (IID 76.23%, 둘 다 시드 0의 36\~40라운드 평균). 40라운드 한 시점 값은 74.36%
  - 클래스별: 클래스 3 50%, 클래스 2 58%로 낮고, 나머지는 65\~84%
  - 클라이언트별 성능(분포 가중 정확도): 0.67\~0.79
  - 업데이트 노름이 IID보다 작다 (90% 지점 2.74, IID 3.40)
- 결과 폴더: `experiments/norm_check/label_skew-normal-fedavg-s0/`

## ⑤ 정상·공격 × 집계 방식 비교
> 각 환경에서 정상·내부자 협력 공격을 FedAvg·클리핑·중앙값 집계로 비교. 환경 요인은 한 번에 하나씩 변경

**구현 내용**
- `scripts/run_matrix.py`: 환경 4 × (정상, 공격) × (FedAvg, 클리핑, 중앙값) × 시드 0·1·2 = **72회**. 실행마다 서버를 새로 띄우고 테스트셋 평가까지 한다
- 끊기면 같은 명령으로 이어서 실행한다. 이름이 같은 기존 결과라도 설정(학습·환경·참여 수·최소 채택 수·공격·방어·라운드 수)이 다르거나, 끝까지 가지 않은 결과(검증·테스트 정확도가 없거나 0\~1 사이 숫자가 아님, `rounds_completed`가 라운드 수와 다름, 로그에 라운드·ID별 행이 빠지거나 중복됨, `env.json`을 읽을 수 없음)나 기기·GPU 모델명·torch 버전이 다른 결과는 재사용하지 않고 멈춘다. `models/`는 커밋하지 않으므로 완료 판정에 쓰지 않는다(자세한 조건: [scripts/README.md](../scripts/README.md))
- 결과 요약: `experiments/matrix/runs.csv`. 실행마다 기기·GPU 모델명·torch 버전·커밋, 발산 라운드도 남긴다

```bash
python scripts/run_matrix.py --dry-run          # 72회 목록과 상태
python scripts/run_matrix.py --seeds 0 1 2      # 본 실험 (MPS 약 3시간)
```

**결과** (11/20, MPS, 커밋 67cb9cc. 72회 모두 완료, 결과 `experiments/matrix/runs.csv`)
- 동작 확인: 공격을 켠 12조합(환경 4 × 집계 3)을 2라운드씩 돌려 모두 정상 종료, 로그 빈칸 없음
- 재현성: 기준·정상·FedAvg·시드 0을 다른 prefix(`experiments/matrix_repeat/`)로 한 번 더 돌렸더니 정확도와 학습·평가 지표(손실, 노름, 클래스·클라이언트별 정확도)가 일치했다. 다른 것은 실행 시간 열(`train_sec` 등), 실험 이름, 서버 포트뿐이다. 확인한 것은 이 한 조합뿐이라, 다른 조합(특히 공격·클리핑·중앙값)의 시드 간 차이에 실행마다의 흔들림이 섞였는지는 배제하지 못한다

관찰
- **공격 + FedAvg는 모든 환경·시드에서 발산했다.** 발산은 레이블 편향(4\~6라운드)과 지연(6\~8라운드)에서 빨랐고 기준·부분 참여(8\~17라운드)에서 늦었다. 지연 환경은 채택 7명 중 악성이 2명(0.29)이라 집계에서 악성 비중이 크다. 원인은 6단계에서 확인한다
- **두 방어 모두 발산을 막았지만 정상 수준까지는 아니다.** 공격 + 방어는 정상 FedAvg보다 평균 7.07\~14.58%p 낮다(기준 8.77 / 7.07, 지연 14.58 / 11.94, 부분 참여 9.55 / 8.71, 레이블 편향 14.49 / 13.43, 클리핑 / 중앙값). 기준 환경보다 다른 세 환경에서 더 낮다
- **중앙값과 클리핑:** 기준·지연에서는 세 시드 모두 중앙값이 높다(평균 +1.70, +2.64%p). 부분 참여(−0.18 / +0.36 / +2.34)와 레이블 편향(−0.10 / −0.42 / +3.70)은 시드마다 엇갈리고, 평균 차이(+0.84, +1.06%p)는 한 시드의 큰 차이에서 나온다
- **정상 손실은 거의 없다.** 시드별 −0.45\~+0.76%p로 시드 간 차이와 비슷한 크기이고, 레이블 편향의 중앙값만 세 시드 모두 양수(+0.43\~+0.76)다
- **레이블 편향의 정상 클리핑은 정상 FedAvg와 완전히 같다.** 정상 업데이트 노름이 최대 3.13\~3.19로 상한 3.5를 넘지 않아 잘린 업데이트가 0개였다(기준 환경은 400개 중 21·30·14개). 클리핑이 아무것도 바꾸지 않은 것이지 오류가 아니다

## ⑥ 같은 환경·시드의 일정 공유와 시드 반복
> 동일 환경·시드에서는 초기 모델·분할·악성 ID·참여·지연 일정을 공유. 다른 시드로 반복하고 실행한 시드와 결과를 함께 기록

**구현 내용**

- 시드 0·1·2로 반복한다. 결과 폴더 이름(`<환경>-<normal|attack>-<집계>-s<시드>`)과 `config.yaml`에 시드·일정이 남는다

**결과:** 같은 시드면 집계 방식·공격 여부가 달라도 일정이 같음 (테스트)

## ⑦ 모델 역추적은 분리

**구현 내용**

## 한계
- **분할은 시드마다 같다.** 시드 0·1·2는 초기 모델·미니배치 순서·악성·지연·참여 일정만 바꾸고 데이터 분할(IID, 레이블 편향 α 0.5)은 하나로 고정한다. 그래서 시드 간 차이는 "같은 데이터 배정에서의 흔들림"이고, 분할을 바꿨을 때의 차이는 포함하지 않는다
- **같은 설정을 다시 돌려도 비트 단위로 같지 않을 수 있다.** 기기는 cuda → mps → cpu 순서로 자동으로 고르고, GPU 연산 순서 때문에 정확도가 조금 다를 수 있다 (`set_seed`는 `cudnn.deterministic`만 켬). 본 실험은 한 기기에서 돌리고 **끊기면 같은 Mac에서 이어서 실행한다**. 이어서 실행할 때 기기·GPU 모델명·torch 버전이 저장된 결과와 다르면 `stale`로 멈추고, 커밋만 다르면 경고만 낸다. MPS는 GPU 모델명이 비어 있어 서로 다른 Mac은 이 검사로 구분하지 못한다. 한 조합을 **다른 `--prefix`로** 한 번 더 돌려 차이를 쟀고(같은 prefix면 끝난 실행으로 보고 건너뜀), 기준·정상·FedAvg·시드 0 한 조합은 같은 Mac에서 차이가 0이었다(⑤). 다른 조합과 다른 기기에서는 확인하지 않았다. `runs.csv`에 실행마다 기기·GPU 모델명·torch 버전·커밋이 남아 다른 환경의 결과가 섞였는지 확인할 수 있다
- **공격 실험은 발산한다.** 본 실험에서 공격 + FedAvg 12회가 모두 4\~17라운드에 발산했고(예: 기준·시드 0은 1라운드부터 검증 정확도 10% 안팎, 13라운드에 로컬 학습 손실 NaN), 방어를 켠 공격 실험과 정상 실험은 발산하지 않았다. 1라운드 발산은 없었다
  - 처리: 발산하면 그 실행을 끝내고 발산 전(위 사례는 12라운드) 전역 모델로 최종 정확도를 계산한다. 1라운드 집계 직후 깨지면 평가할 모델이 없으므로 정확도 없이 `diverged` 상태로 남기고 다음 조합을 실행한다. 정상 실행의 발산은 결과로 인정하지 않고 멈춘다(정상 기준값이 짧은 학습으로 바뀌지 않게)
  - 비교표: 주 표는 40라운드 기준으로 비교하고, 발산한 칸은 숫자 대신 **발산(13라운드)**처럼 표시한다. 발산 직전 모델의 정확도는 `summary.json`·`runs.csv`에 그대로 보존해 별도로 적는다. 발산 직전 모델(예: 12라운드)과 정상 40라운드 모델의 차이에는 학습 길이 차이도 들어가므로 같은 열에서 빼지 않는다. 최종 표기 방식은 팀이 정한다
