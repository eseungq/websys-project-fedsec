## ① 기준
> 기준: 참여율 100%, 지연 없음, 클래스 분포가 비슷한 데이터

**구현 내용:** 매 라운드 10명 전원 참여, 지연 클라이언트 0명. 분할은 팀 공용 `configs/splits/iid_seed0.json`(레포 루트): CIFAR-10 학습 50,000장 → 클라이언트 10명 × 4,500장 + 검증 5,000장. 공식 테스트 10,000장은 최종 평가에만 쓴다.

**결과**
- 2라운드 확인: 매 라운드 10명 채택, 실제 채택 악성 비율 0.2, 가상 경과 시간 1.0
- 정상 FedAvg 40라운드 검증 정확도 76.38% (36\~40라운드 평균, 시드 0\~2 평균, [1_학습설정-결과.md](1_학습설정-결과.md))

## ② 지연
> 기준에서 고정된 3개 클라이언트만 가상 마감 시각 초과. 지연·마감 값은 팀이 정하고, 실제 순차 실행 시간과 분리하여 채택 여부 판정

**구현 내용**
- 가상 완료 시각 = 기본 계산 1.0 × (표본 수 / 4,500) + 지연 2.0(지연 클라이언트만). 마감 1.5
- 그래서 정상은 1.0으로 채택되고, 지연 3명은 3.0으로 **항상** 마감을 넘어 `late`로 제외된다 (클라이언트 표본 수가 모두 4,500장이라 라운드마다 같다). 설정 값을 바꿔 "지연 클라이언트만 마감 초과"가 깨지면 클라이언트가 학습 전에 멈춘다
- 지연 3명은 시드로 고정하고 악성과 겹치지 않게 뽑는다 (시드 0: 0·4·9번)
- 채택 여부는 가상 시각으로만 정한다. 실제 실행 시간(`train_sec`, `comm_sec`, `total_sec`)은 따로 기록한다

**결과 (2라운드 확인):** 매 라운드 선택 10, 채택 7, `late` 3. 악성 2명이 모두 채택되어 **실제 채택 악성 비율 0.29**(2/7)로 전체 악성 비율 0.2보다 높다. 가상 경과 시간 1.5(늦은 제출이 있으면 마감 시각).

## ③ 부분 참여
> 기준에서 라운드마다 10개 중 5개를 무작위 선택

**구현 내용:** (시드, 라운드)로 참여자 5명을 정한다. 공격 여부·집계 방식이 달라도 같은 라운드에는 같은 5명이 참여한다. 서버가 참여자를 알고, 참여자가 아닌 제출은 `not_selected`로 제외한다.

**결과**
- 매 라운드 정확히 5명 (테스트)
- 2라운드 확인: 1라운드 참여 2·3·5·6·7번(악성 2명, 공격 적용, 실제 채택 악성 비율 0.4), 2라운드 0·4·7·8·9번(악성 0명, 공격 미적용)
- 시드 0, 40라운드 동안 참여 악성 수: 0명 6회, 1명 21회, 2명 13회

## ④ 레이블 편향
> 기준에서 같은 데이터의 클라이언트 배정만 변경. 클라이언트별 표본 수는 유지

**구현 내용**
- IID 분할과 **같은 검증 세트, 같은 이미지 풀**에서 배정만 바꾼다
- 클라이언트별 클래스 비율을 Dirichlet(α = 0.5)로 뽑고, 클라이언트당 4,500장과 클래스별 장수를 정확히 맞춰 배정
- 분할 파일: `configs/splits/label_skew_a0.5_seed0.json` (이 폴더). 시드와 관계없이 이 분할을 쓴다
- 만드는 명령: `python scripts/make_split.py --kind label_skew --alpha 0.5 --seed 0`, 분포 보기: `--show-dist`

**결과**
- 행(클라이언트 4,500장)·열(클래스별 장수) 합과 검증 세트가 IID와 같음 (테스트)
- 치우침: 클라이언트마다 가장 많은 클래스가 22\~62%를 차지하고(IID는 약 10%), 100장 미만인 클래스가 1\~5개 있다. 가장 치우친 클라이언트 4는 클래스 2가 2,790장(62%)
- 정상 FedAvg 40라운드(시드 0, 서버 경유): 검증 정확도 **73.80%** (IID 76.23%, 둘 다 시드 0의 36\~40라운드 평균). 40라운드 한 시점 값은 74.36%
  - 클래스별: 클래스 3 50%, 클래스 2 58%로 낮고, 나머지는 65\~84%
  - 클라이언트별 성능(분포 가중 정확도): 0.67\~0.79
  - 업데이트 노름이 IID보다 작다 (90% 지점 2.74, IID 3.40)
- 결과 폴더: `experiments/norm_check/label_skew-normal-fedavg-s0/`

## ⑤ 정상·공격 × 집계 방식 비교
> 각 환경에서 정상·내부자 협력 공격을 FedAvg·클리핑·중앙값 집계로 비교. 환경 요인은 한 번에 하나씩 변경

**구현 내용**
- `scripts/run_matrix.py`: 환경 4 × (정상, 공격) × (FedAvg, 클리핑, 중앙값) × 시드 0·1·2 = **72회**. 실행마다 서버를 새로 띄우고 테스트셋 평가까지 한다
- 끊기면 같은 명령으로 이어서 실행한다. 이름이 같은 기존 결과라도 설정(학습·환경·참여 수·최소 채택 수·공격·방어·라운드 수)이 다르거나, 끝까지 가지 않은 결과(검증·테스트 정확도가 없거나 0\~1 사이 숫자가 아님, `rounds.csv` 줄 수가 라운드 수와 다름, 최종 모델 없음)는 재사용하지 않고 멈춘다
- 결과 요약: `experiments/matrix/runs.csv`. 실행마다 기기·torch 버전·커밋도 남겨, 다른 환경의 결과가 섞였는지 보이게 한다

```bash
python scripts/run_matrix.py --dry-run          # 72회 목록과 상태
python scripts/run_matrix.py --seeds 0 1 2      # 본 실험 (MPS 약 3시간)
```

**결과**
- 동작 확인: 공격을 켠 12조합(환경 4 × 집계 3)을 2라운드씩 돌려 모두 정상 종료, 로그 빈칸 없음
- **본 실험 결과와 공격 피해·방어 개선·정상 손실(%p)은 아직 없다.** 실행 뒤 아래 표를 채운다

| 환경 | 공격 피해 | 방어 개선 (클리핑 / 중앙값) | 정상 손실 (클리핑 / 중앙값) |
|---|---|---|---|
| 기준 | | | |
| 지연 | | | |
| 부분 참여 | | | |
| 레이블 편향 | | | |

(명세 정의: 공격 피해 = 정상 FedAvg − 공격 FedAvg, 방어 개선 = 공격+방어 − 공격 FedAvg, 정상 손실 = 정상 FedAvg − 정상+방어. 같은 환경·시드의 최종 테스트 정확도 차이를 %p로, 시드별 값과 평균을 함께 쓴다)

## ⑥ 같은 환경·시드의 일정 공유와 시드 반복
> 동일 환경·시드에서는 초기 모델·분할·악성 ID·참여·지연 일정을 공유. 다른 시드로 반복하고 실행한 시드와 결과를 함께 기록

**구현 내용**
- 초기 모델은 서버가 시드로 만든다. 악성·지연·참여 일정도 시드로만 정한다 (용도별로 난수를 분리해 서로 섞이지 않음)
- 분할은 시드와 관계없이 고정. 시드가 바꾸는 것은 초기 모델, 미니배치 순서, 악성·지연·참여 일정
- 시드 0·1·2로 반복한다. 결과 폴더 이름(`<환경>-<normal|attack>-<집계>-s<시드>`)과 `config.yaml`에 시드·일정이 남는다

**결과:** 같은 시드면 집계 방식·공격 여부가 달라도 일정이 같음 (테스트)

| 시드 | 악성 | 지연 |
|---|---|---|
| 0 | 2, 3 | 0, 4, 9 |
| 1 | 1, 4 | 3, 5, 9 |
| 2 | 5, 7 | 6, 8, 9 |

## ⑦ 모델 역추적은 분리
> 모델 역추적은 위 학습 성능 비교와 분리하여 수행. 동일 이미지의 노이즈 수준별 복원 결과를 비교하고, 사용 이미지와 반복 횟수는 팀이 정해 기록

**구현 내용**
- 연합학습 실험과 분리된 `scripts/run_dlg.py` (CPU)
- 같은 이미지 5장에 노이즈 수준만 바꿔 비교. 이미지는 클라이언트 0에서 클래스가 겹치지 않는 앞쪽 5장(1 truck, 27 dog, 38 cat, 52 horse, 61 automobile), 반복 300회 (원 논문 코드와 같음)
- 이미지·σ·반복 횟수·시드는 `configs/dlg.yaml`과 결과 폴더의 `config.yaml`에 기록

**결과:** σ 0 / 1e-2 / 1e-1 → MSE 0.00005 이하 / 0.05\~0.08 / 0.26\~0.31. 반복 횟수만 바꾼 실험(50·300·1000회)에서 σ 0은 80\~130회면 충분했고 1000회도 결과가 같았다. 자세히: [3_DLG-결과.md](3_DLG-결과.md), [3_공격-방어.md](3_공격-방어.md) ④
